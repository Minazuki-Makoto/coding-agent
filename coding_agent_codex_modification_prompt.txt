
开始前完整阅读 AgentLoop、State、Context、MCP_functions、Skills、tests 和 PROBLEM.md 中与本任务有关的代码。不要只修改提示词，必须完成代码修改和测试。

一、不得改变的架构

1. 保留 Supervisor 的 planning、initial guidance、evaluation、decision 四个阶段。
2. 保留 Executor 针对当前 task 的 ReAct 工具执行循环。
3. 保留 Supervisor 否决权；即使 Executor 返回 is_finished=true，Supervisor 仍可要求继续当前 task。
4. task_id 只有 Supervisor decision 允许推进时才能增加。
5. Executor 单次 run_executor_loop 内继续维护最多 10 条 description 的局部窗口。
6. 每次重新进入 Executor/Supervisor 时仍可清空局部运行态。
7. JSONL 继续采用追加写，不回写旧记录。
8. 历史工具继续只授予 Supervisor，Executor 不直接查询历史。
9. 不把完整历史塞回模型上下文，不删除唯一的原始工具证据。
10. 不重构 MCP Host、ToolRegistry 和 Supervisor/Executor 的总体职责边界。

二、增强 Supervisor → Executor 的交接

当前 Supervisor 主要通过 executor_plan 传递 instruction。增加结构化 SupervisorHandoff（名称可按项目风格调整），至少包含：

- supervisor_seq
- task_id
- target
- instruction：本轮要求 Executor 做什么
- previous_work：前几轮已经做过什么
- accepted_work：Supervisor 已验收认可、无需重做的内容
- remaining_work：当前仍缺什么
- completion_criteria：task 创建时锁定的原始完成条件
- evidence_locators：有效证据对应的 task_id + tool_event_seq
- completed_tool_calls：已成功且不应无理由重复的工具调用指纹

第一次进入 task 时 previous_work 和 accepted_work 为空；Supervisor 否决后，下一次交接必须说明已接受内容、剩余缺口和本轮精确动作，不能只写“继续当前任务”。

三、锁定 task 原始完成条件

在 AgentState 中增加按 task_id 保存的原始 completion criteria。initial guidance 创建后锁定；evaluation 每轮都接收同一份原始条件；decision 只能更新 remaining_work 和本轮验证要求，不能静默覆盖原始条件。verification_requirement 只表示本轮补充要求。用户要求变化时必须显式记录条件变更。

四、修正 Executor 输入构造

当前 _reset_executor_turn 保存了 executor_state.supervisor_guidance，但 _build_executor_messages 又直接读取 supervisor_state.executor_plan；executor_state.input_content 直到循环结束才构造。修正为：

1. 在 _reset_executor_turn 中立即构造完整 executor_state.input_content。
2. input_content 至少包含 task_id、task_attempt、target 和完整 SupervisorHandoff。
3. _build_executor_messages 使用 executor_state.input_content 快照，不再依赖可变的 supervisor_state.executor_plan。
4. 模型实际看到的输入与最终写入 executor_turn 的 input_content 必须一致。
5. Executor 模型接收 step、max_steps、recent_descriptions、environment 和 skills。
6. Executor 没有历史工具权限，因此 session_address/chat_id 留在 Host 状态用于持久化，无需默认暴露给 Executor 模型。
7. 如果启用 Executor skill 选择，skill selector 也必须看到 Supervisor instruction、previous_work、accepted_work 和 remaining_work。

五、保留现有 Executor description 机制

保留现有链路：每次真实工具结果经过 _summarize_tool_once 生成 description，加入 descriptions 和长度 10 的 memory_window，Executor 循环结束后由程序确定性拼接为 output_content。

禁止在 Executor 返回 Supervisor 前再次调用模型总结全部 descriptions。input_content 只表达 Supervisor 给了什么；output_content 只表达 Executor 本轮做了什么；不要把完整 Supervisor 输入复制到 output_content。

为 executor_turn 增加结构化 tool_summaries，每条至少包含 tool_event_seq、tool_name、tool_ok、description，建立总结与原始工具事件的一一对应。

六、消除模型上下文中的工具结果重复

当前工具执行后，_build_executor_messages 通过 latest_tool_observation 放入一次 tool_result，随后 build_tool_observation_messages 又放入一次。增加 include_latest_tool_observation 等控制参数：工具刚执行完并准备 _summarize_tool_once 时只使用标准 tool observation，不再同时传 latest_tool_observation。普通后续 ReAct 如需最近 observation，可以传一次，但同一模型请求不能出现两份相同原始结果。

七、原始 tool_result 只持久化一次

原始 tool_result 必须保留，但只允许出现在对应 tool_event。

Executor：
- 每次真实工具调用立即保存一个 tool_event，包含 tool_name、arguments、tool_result、tool_ok。
- Executor 循环结束保存一个 executor_turn，包含 input_content、output_content、tool_event_seqs、tool_summaries、完成和错误状态。
- executor_turn 不再复制完整 tool_result 和 tool_arguments。
- 不要通过清空当前运行态实现去重；由 save_state_history 按 record_type 构造不同记录。

Supervisor：
- planning/evaluation/decision 的工具事件可以各保存一次完整查询结果。
- planning_turn、evaluation_turn、decision_turn、final_summary_turn 不得继续复制完整 tool_result，只保存 tool event seq、description、判断和控制字段。

重要：一次 Executor 执行周期不是固定保存两次。如果调用 N 个工具，应该保存 N 条 tool_event，再保存 1 条 executor_turn，即 N+1 条。若只调用 1 个工具，则正好保存两条。完整 Supervisor 验收后还可以在 executor_history 中追加一条 supervisor_review。不得为了去重删除这些不同职责的记录，只删除相同原始内容的复制。

八、拆分 Executor seq 类型

当前 passed_seq_list 混合 tool_event seq 和 executor_turn seq。替换为：

- tool_event_seqs: list[int]
- executor_turn_seq: int | None

真实工具调用只加入 tool_event_seqs；最终 turn 的 seq 单独写入 executor_turn_seq。Supervisor evaluation 的工具 locator 只指向 tool_event；Executor 最终汇总通过 executor_turn_seq 单独定位。Decision 同时接收准确的工具 locator、executor turn locator 和 evaluation locator。

九、历史工具参数由 Host 绑定

保留 Supervisor 消息中的 session_address/chat_id/task_id，但历史工具真正调用前由 Host 对当前会话强制补充或覆盖 session_address/chat_id，不完全信任模型生成值。模型负责选择历史工具及 task_id/seq；Host 校验 task_id/seq 类型和允许范围。只对历史工具实施该绑定，不影响其他 MCP 工具。

Planning 在 task 尚未创建时主要使用 read_history_chat。Evaluation 接收当前 task、原始 completion criteria、Executor input/output 和精确 locators。Decision 也接收 Executor tool locators、executor_turn locator、evaluation locator、accepted_work 和 remaining_work，并据此生成下一轮 SupervisorHandoff。

十、修复 write_in_tool 并新增精确替换工具

当前 write_in_tool 描述声称覆盖和确认，实际使用 open(..., "a") 追加、没有确认、没有路径限制且返回 None。必须修复：

1. write_in_tool 定义为完整文件覆盖工具，code 是完整目标文件内容。
2. 默认覆盖，不得追加；使用临时文件和原子替换，避免部分写入。
3. 规范化真实路径并限制在 Host 配置的可信可写根目录内；不信任模型传入 allowed root；防止 .. 和符号链接逃逸。没有可信根目录时失败关闭。
4. 返回 status、operation、file_address、created、changed、bytes_written 等结构化字段，不得返回 None。
5. 描述必须与真实行为一致。没有真正 Host approval 协议时，不得继续声称 Request approval。

新增 str_replace_tool，至少接收 file_address、old_text、new_text、expected_replacements=1。old_text 不存在或匹配次数不符时拒绝修改；替换后重新读取验证；使用相同路径边界；返回结构化结果。将新工具注册给 Executor，并更新 supervisor_plan.md。

十一、Supervisor 全阶段结构化输出有界重试

所有 parse_json_object、Pydantic 校验和后续语义校验失败都必须反馈模型并在预算内重试，不得直接逃出 run_supervisor_loop 终止请求。

Planning：直接 JSON 和历史工具后的 summary 两条路径都捕获 ValueError/ValidationError，写入 validation_error 和反馈后 continue；工具已成功时不得因 summary 校验失败重复工具。给 PlanningResult 增加 ConfigDict(extra="forbid")。

Initial guidance：增加独立有界重试循环，处理非 JSON、缺字段、多字段和类型错误；只有达到上限后才返回明确 blocked 原因。

Evaluation：直接 JSON 和工具后的 summary 两条路径都捕获校验错误，写入 evaluation memory_window，保存 evaluation_validation_error，再 continue；已经执行成功的历史工具不得重复调用。

Decision：保留现有 Pydantic 重试，并将 _validate_decision_plan(now_state, result) 放入同一个 try；任务列表语义错误必须反馈重试。

所有重试受 max_supervision_times 和 max_model_requests 限制。同步修正 PROBLEM.md 中“所有 Supervisor JSON 校验已经反馈重试”的不准确信息。

十二、测试与验收

至少覆盖：

1. Supervisor 第二次指导同一 task 时传入 previous_work、accepted_work、remaining_work。
2. Executor 重入仍清空局部 memory_window，但收到 Supervisor 的前序工作交接。
3. Executor 模型实际输入与保存的 input_content 一致。
4. output_content 仍为本轮 descriptions 的确定性拼接，没有额外模型总结。
5. 同一 tool_result 在一次模型请求中不重复。
6. 完整 tool_result 只存在于对应 tool_event。
7. executor_turn 和 Supervisor 普通 turn 不复制完整结果。
8. tool summary 能准确引用 tool_event_seq。
9. tool_event_seqs 与 executor_turn_seq 不混合。
10. Supervisor evaluation 和 decision 得到正确 locator。
11. 历史工具调用由 Host 绑定当前 session_address/chat_id。
12. write_in_tool 连续调用时第二次覆盖第一次，不是追加，并返回结构化结果。
13. str_replace_tool 只在匹配次数符合预期时修改。
14. 授权根目录外写入被拒绝。
15. planning、initial guidance、evaluation 的非 JSON、缺字段、多字段都会反馈重试。
16. _validate_decision_plan 抛错会反馈重试。
17. 已成功工具不会因后续 summary 校验失败而重复执行。
18. Supervisor 否决权、task_id 推进和 Executor 十条 description 窗口保持不变。
