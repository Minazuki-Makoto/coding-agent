# Supervisor 记忆检索

本技能是正确性审查和错误审查共用的辅助检索协议。它把“判断哪条旧记忆相关”和“读取该条原始记录”分成两个工具步骤，避免把全部执行历史放入模型上下文。

这里的模糊匹配是模型对 `description` 的语义筛选，不是字符串相似度、关键词计分或向量检索。

## 两种读取路径

- 审查当前 executor 回合时，输入已经提供精确的 `session_address`、`chat_id`、`task_id` 和 `seq`。直接调用 `read_task_error`，不要先做候选匹配。
- 查找可能相关的旧上下文时，先调用 `read_now_task` 获取摘要候选，再按本技能进行选择和精确读取。

## 候选格式

`read_now_task` 返回 JSON 数组，每项格式为：

```json
{
  "description": "供语义相关性判断的历史摘要",
  "locator": {
    "session_address": "已有会话目录",
    "chat_id": "已有聊天编号",
    "task_id": 0,
    "seq": 1
  }
}
```

只允许根据 `description` 判断候选是否相关。`locator` 是不透明的路由信息；不得根据路径文本、编号大小、编号接近程度或字段排列推断相关性。

## 检索流程

1. 使用运行时输入中的 `session_address`、`chat_id` 和当前 `task_id` 调用 `read_now_task`，不得编造或改写这些值。
2. 阅读所有候选的 `description`，选择能直接帮助当前 `target`、当前错误或当前待核验结论的最少候选；允许一个也不选。
3. 每次只选择一个候选，把它的 `locator` 四个字段原样作为 `read_task_error` 的参数，不补字段、不改编号、不拼接路径。
4. 精确记录返回后，核对工具输入、输出、错误和 supervisor 总结。若证据已足够，立即停止读取；确有必要时才读取下一个候选。
5. 连续读取多个候选时，在下一次工具调用所附的普通文本中保留已确认事实的简短描述，因为 AgentLoop 下一内部步骤只保留该描述和最近一次工具观察。

## 边界

- 空数组表示没有候选，不表示任务正确、完成或没有当前错误。
- `description` 为空、含义不足或仅有宽泛词语时，不得据此选择精确记录。
- 候选结构缺字段、locator 类型错误、精确读取为空或工具报错时，停止使用该候选并如实说明证据不足，不得猜测定位字段。
- 历史只提供线索。历史内容与当前文件、当前工具结果或当前用户要求冲突时，以当前可验证证据和最新要求为准。
- 读取历史不会恢复 AgentState，也不会回滚文件、数据库、进程或外部服务状态。
